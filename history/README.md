# history — 작업 기록

**원칙: 판단이 들어간 작업은 결과만 남기지 말고 근거와 날짜를 같이 남긴다.**
나중에 수정하거나 다시 볼 때 "그때 왜 그렇게 정했는지"를 알 수 있어야 한다.

```
history/
  discover/   YYYY-MM-DD.json/.md   아이템 발굴 회차 기록 (discover.py가 자동 생성)
  products/   {상품ID}.md            상품 수집·검증 기록 (수동 작성)
  articles/   {상품ID}.md            글 작성·수정 이력 (수동 작성)
```

---

## discover/ — 자동

`naver-store-extractor/discover.py` 실행 시 자동 저장.

```
python discover.py            # 발굴 실행 + 기록 저장
python discover.py --history  # 과거 회차에서 반복 등장한 키워드 보기
python discover.py --no-ac    # 데이터랩만 (빠름)
```

**축적되면 생기는 것**
- `⭐연속` 표시 — 이전 회차에도 올라온 키워드는 +4점. 2주 연속 상승은 강한 신호다
  (실제로 팁런에기가 3회 연속 올라왔고, 그게 가을 에깅 시즌 시작이었다)
- 계절성 파악 — 작년 같은 시기에 뭐가 떴는지 비교 가능

## products/ — 수동

상품을 수집·검증했으면 채택 여부와 무관하게 기록한다.
**탈락시킨 상품일수록 기록 가치가 높다.** 나중에 같은 상품을 또 검토하는 걸 막아준다.

기록할 것:
- 링크, 가격, 리뷰 수·평점, **1~3점 비율**
- 원산지·옵션 등 판단에 쓴 스펙
- 수집 시 막힌 지점 (캡차, 429 등)
- **채택/탈락 판단과 그 이유**

## articles/ — 수동

글을 쓰면 남긴다. 수정 요청이 들어왔을 때 "왜 이렇게 썼는지"를 되짚기 위한 것.

기록할 것:
- 최종 각도와 **탈락시킨 각도**
- 사용자 피드백으로 바꾼 것 (문체 지적 포함)
- 쓰지 않기로 한 정보와 그 이유 (예: 체험단으로 보이는 5점 리뷰)
- 발행 후 수정이 필요한 시점 (예: 9월에 할인율 변경 예정)
