# 블로그 포스팅 자동화 프로세스

---

## PHASE 0: 아이템 발굴

```
cd naver-store-extractor
python discover.py              # 데이터랩 급상승 → 자동완성 깊이 → 점수화
python discover.py --history    # 과거 회차 반복 등장 키워드
```

- 데이터랩 7일 vs 30일 순위를 비교해 급상승만 추출
- 후보 전량에 네이버 자동완성 조회 → 정보성 접미어(차이·비교·손질·보관 등) 개수로 글감 가치 판단
- **이전 회차에도 올라온 키워드는 +4점** (연속 상승이 가장 강한 신호)
- **B2B / 사무실 관행 조달 품목(A4용지, 토너 등) 자동 제외**: 개인이 네이버에서 직접 검색해 사는 품목이어야 함
- **고관여 실패 위험 / 옵션·호수 비교 품목 가산점(+1.5점)**: 밀본 염색약, 리들샷처럼 호수(b6/b7/b8, 100/300)나 배합 실패를 피하기 위해 검색하는 품목 우선
- **80% 뻥튀기 가짜 정가 품목 탈락**: 정직한 가격대와 오프라인 대비 5~10배 가성비 품목 채택
- 상품권·기프티콘 등 리뷰가 없는 품목은 자동 제외

결과는 `history/discover/YYYY-MM-DD.json/.md`에 자동 저장.

## 기록 원칙 (모든 단계 공통)

**판단이 들어간 작업은 결과만 남기지 말고 근거와 날짜를 같이 남긴다.**

| 무엇 | 어디에 |
|---|---|
| 발굴 회차 | `history/discover/` — discover.py가 자동 생성 |
| 상품 수집·검증 | `history/products/{상품ID}.md` + `_index.md` 한 줄 추가 |
| 글 작성·수정 이력 | `history/articles/{상품ID}.md` |

- **탈락시킨 상품일수록 기록 가치가 높다.** 같은 상품을 또 검토하는 걸 막아준다
- 글은 **최종 각도뿐 아니라 버린 각도와 그 이유**를 남긴다
- 수집 중 막힌 지점(캡차·429·스크립트 버그)도 남긴다
- 자세한 규칙은 `history/README.md`

## PHASE 1: 자료 수집 및 정리

### 입력값
- 스마트스토어 상품 URL (키워드 파일 불필요)

### 처리 순서
1. `python debug_smartstore.py <URL> <PRODUCT_ID>` → 상품 API 데이터 캡처
   > ⚠️ **주의:** 일반 스마트스토어가 아닌 '브랜드 스토어(brand.naver.com)'의 경우 `/products/{PRODUCT_ID}` 대신 `/simple-products?ids=` 형태로 API가 호출될 수 있습니다. 캡처가 안 될 경우 전체 JSON을 스캔(예: `debug_capture_all.py` 활용)하여 수동 추출해야 합니다.
2. Claude Code가 상품 JSON 분석 → 상품명·카테고리·태그·옵션·상세설명 추출
3. 인터넷 트렌드 조사 → 네이버 자동완성 API + 웹 검색으로 연관 키워드 핫 이슈 발굴
4. **검색량 수치 사용 금지** — 실제 트렌드 근거(출처 명시)로만 키워드 우선순위 판단
5. 구매 페르소나 역설계
   - 상세페이지 문구만 보고 추정하지 말고, 제품명·카테고리·원재료를 직접 검색해 "실제로 이런 제품을 누가, 어떤 상황에서, 왜 찾고 만족하는지"를 후기·커뮤니티·블로그에서 확인
   - 페르소나별로 ① 페인 포인트(불편함) ② 이 제품에서 얻는 좋은 인상·감상(만족 포인트)을 함께 도출

> ⚠️ 키워드 검색량은 Naver Keyword Planner 실측치가 있을 때만 기재.
> 없을 경우 "추정치" 표기 대신 트렌드 근거(언론·자동완성·SNS)로 대체.
>
> ⚠️ 페르소나는 "상세페이지 재구성"이 아니라 "검색 후 들어온 독자가 무엇을 기대하고, 무엇에 만족할지"를 기준으로 설계할 것.

### 산출물
```
output/{product_id}/
  product.json       # 정형 데이터
  product.md         # 블로그용 요약
  screenshot_*.png   # 상세이미지 원본
keyword_analysis.md  # 키워드 분석 + 페르소나
```

## PHASE 2: 블로그 글 작성

> **글 쓰기 전에 `prompts/07_writing_style.md`를 반드시 먼저 읽을 것.**
> 블로그 후기글 102편 실측 기반 문체 규칙 (문장·문단 길이, 어미 비율, 정서 기호 빈도, AI 티 제거).
> 카테고리별 세부 수치는 `prompts/06_style_corpus.md`.

### 구조
```
상품 타겟에 적합한 최적 2인 앵글 선정 (5대 라이브러리 중)
    ↓ Draft A vs Draft B 대조 작성 (깊이 있는 분량과 디테일)
편집장 채점 (100점 만점)
    ↓ 점수 + 피드백
우수 초안을 기반으로 강점 통합본 완성
    ↓
최종 본문 + 제목 3~5개 + 사진 배치 지시서 + 태그 10~15개
    ↓
타겟층 시점 최종 검수 (Phase 3)
    ↓
검수 통과 시 → 확정 / 미통과 시 → 지적 항목만 수정 후 확정
```

### 편집장 채점 기준 (각 25점)
| 항목 | 기준 |
|---|---|
| 분량 | 1,500~2,500자. 초과/미달 시 감점 |
| 키워드 | 핵심 키워드 3개 이상 자연스럽게 포함 |
| 사실성 | product.json 기반 검증 가능한 내용만 |
| 자연스러움 | `07_writing_style.md` 체크리스트 통과 필수(문장 중앙값 20자 미만, 어미 혼용, AI 티 항목). 읽다가 "이거 광고네" 느낌 드는 문장 없어야 함. 성분·스펙을 상세페이지 그대로 나열(복붙)하지 말고, 독자가 "이게 나한테 필요하다"는 감상을 느끼도록 풀어서 설명 |

## PHASE 3: 타겟층 시점 최종 검수

### 목적
편집장 기준(형식·키워드·사실)을 통과한 글이 **실제 독자에게도 자연스럽게 읽히는지** 확인.
편집장이 못 잡는 맥락 오류(화자 시점 불일치, 흐름 단절, 구매 연결 누락)를 잡는 단계.

### 검수 방법
keyword_analysis.md에서 도출한 구매 페르소나 3명이 **실제 검색 후 유입된 독자 시점**으로 글을 처음부터 읽는다.

각 페르소나마다 아래 4가지를 확인:

| 체크 항목 | 질문 |
|---|---|
| 유입 적합성 | 내가 검색한 키워드로 이 글이 나왔을 때 클릭할 만한가? |
| 공감 지속 | 읽다가 "나 얘기 아닌데" 싶은 순간이 있는가? |
| 정보 충족 | 내가 궁금했던 것(어떤 야채, 얼마, 어디서)이 해결됐는가? |
| 행동 유도 | 다 읽고 나서 다음에 뭘 해야 할지 알 수 있는가? |

### 통과 기준
- 3명 중 2명 이상: 4개 항목 모두 OK → 확정
- 1개라도 NO가 나온 항목 → 해당 부분만 수정 후 재확인 (전체 재작성 없음)

### 자주 발견되는 오류 패턴
1. **화자 시점 불일치** — 글쓴이 경험이 독자 상황과 맞지 않음 (예: 첫째 이유식 독자에게 "둘째 때 알았다")
2. **흐름 단절** — 감성 서술 중 갑자기 표·스펙 나열로 전환
3. **구체성 부족** — 실제 어떤 제품을 샀는지, 아기 반응이 어땠는지 없음
4. **구매 연결 누락** — 감성 마무리 후 "그래서 어디서 사요?"에 대한 답 없음
5. **광고 패턴 문장** — "강추", "사용은 진짜 간단해요" + 바로 가격 나열
